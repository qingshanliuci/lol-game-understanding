# 方法论

## 1. 记录单位

每次更新必须写明：

- `as_of`：冻结日期与时间；
- 赛区、赛段和 patch；
- 样本窗口与局数；
- 结论状态：`provisional` / `supported` / `falsified`；
- 最强反证与下一次验证动作。

当天刚结束的比赛可以加入观察层，但不能偷偷改写赛前先验；若判断变化，应说明由哪条新证据触发。

## 2. 英雄层级

### 2.1 六维评分卡

每个候选英雄按六个问题检查，不强求伪精确总分：

| 维度 | 核心问题 |
|---|---|
| BP 优先级 | 是否频繁进入首轮 pick/ban，或迫使对手改变 BP？ |
| 盲选安全 | 对线、边线、团战中是否存在容易被稳定利用的硬缺口？ |
| 对线下限 | 没有打野倾斜时能否保持可玩的血量、兵线与经验？ |
| 阵容适配 | 能否进入多种伤害结构和开团方式，而非锁死其余四手？ |
| 逆风功能 | 落后时是否仍有控制、前排、保护、清线、边线牵制或安全输出？ |
| 领先转化 | 拿到经济后能否稳定转成视野、资源、塔或团战胜势？ |

### 2.2 标签

- **blind T0**：可以较早选，缺陷难被常规 BP 稳定惩罚。
- **counter T0**：后手进入正确对位或阵容时可达到 T0 价值，不等于能盲出。
- **T1**：强且常用，但至少一个关键条件明显弱于 T0。
- **comfort**：强度依赖特定选手熟练度，不外推为赛区通用答案。
- **trap**：选用频繁或名义价值很高，但常需要未被满足的先决条件；不是“这个英雄永远不能选”。
- **provisional**：证据尚不足，当前只是可推翻的工作结论。

### 2.3 版本陷阱判定

至少回答四个问题：

1. 它承诺解决什么问题？
2. 它实际把什么职责转嫁给了队友？
3. 哪个经济或装备断点一旦错过，价值会骤降？
4. 反例是否来自队伍实力，而不是英雄机制？

例如，鳄鱼只有在“需要短周期上野对抗、有人承接第一轮之后的持续输出、且能兑现先锋/塔皮”时才成立。若把它当稳定前排或后期兜底，它就是条件性陷阱。

## 3. 阵容理解：伤害交付链

不以“控制多”“有 AP”“前排多”直接判定阵容好坏。按顺序追踪：

1. **创造接触**：谁能逼对手进入战斗，而不只是理论上有控制？
2. **第一轮控制/伤害**：第一套技能能否命中同一目标？
3. **进场存活**：发起者是否能活到队友跟上？
4. **第二轮技能**：第一波未击杀时，谁维持阵型和输出？
5. **持续输出**：面对前排、龙区或拉扯局面，伤害是否会断？
6. **收割与追击**：残血目标能否被稳定处理？
7. **资源转化**：赢团后能否拿塔、龙、男爵或边线，而不只是多几个人头？

同时记录经济落点：关键经济若落在无法完成当前职责的位置，账面领先需要折价。

## 4. 逆风阵容

### 4.1 收录门槛

候选案例至少满足一种：

- 15 或 20 分钟落后至少 500 金后取胜；
- 中期资源/地图状态明显不利后完成可定位的状态翻转；
- 复盘能指出机制链，而不是只写“选手操作好”。

### 4.2 升级规则

- `candidate`：单局或少量同队案例，只能说明“这套阵容曾如何翻盘”。
- `validated`：核心机制跨队伍、跨对手复现，并有足够对照样本；至少记录失败反例。

升级前比较的不是五个英雄是否完全相同，而是核心机制是否相同，例如“可牺牲第一前排 + 保护型辅助 + 能打第二轮的双 C”。

## 5. 从认知到预测

认知台账中的结论默认不直接进入交易或 live bot。进入预测系统前至少完成：

1. 固定特征定义和统计窗口；
2. 时间顺序 holdout；
3. 与 Elo/经济/队伍状态基线比较 Brier、LogLoss 与校准；
4. 加入市场价格后的消融；
5. 计入手续费、滑点和执行误差后的净 EV。
